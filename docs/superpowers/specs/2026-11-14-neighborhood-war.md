# מלחמת שכונות (Territory War) — MVP (2026-11-14)

## למה
פיצ'ר גיימיפיקציה מבוסס-מיקום: אוהדים מגיעים פיזית, "כובשים" אזור, והוא נצבע בצבע הקבוצה. מטרה: מעורבות באמצע-השבוע, גאוות-שכונה, תחרותיות. הבעלים בחר **MVP עכשיו** (כיבוש + מפה + צביעה), טבלאות-מובילים וליטושים אחרי; יחידת-כיבוש = **רשת הקסגונים**.

## אמת הנדסית (נאמר לבעלים)
onefan היא **PWA ווב**, לא נייטיב. אי אפשר לזהות mock-location, לקרוא אנטנות סלולר או חיישנים כמו בנייטיב. לכן ההגנה היא **צד-שרת בלבד**, טובה-מספיק נגד רמאות מזדמנת ולא חסינה מול רמאי נחוש. נייטיב בעתיד = הגנה חזקה יותר.

## החלטות הנדסיות (קריאה של Claude)
- **בלי PostGIS. H3 (h3-js) מחושב בשרת.** המכשיר שולח רק lat/lng(+accuracy); ה-Server Action (צד-שרת, אמין) מחשב את תא-ההקס — כך הלקוח לא יכול לזייף תא. רזולוציה **8** (~460מ' קצה, "שכונה").
- **הכתיבה רק דרך Server Action עם service-role.** טבלת `territory` היא **קריאה-בלבד ללקוחות** (RLS select בלבד, אין insert/update/delete) — כך אי אפשר לכבוש בלי לעבור את הבדיקות.
- **בדיקות אנטי-רמאות בשרת:** סף-דיוק (דוחים accuracy גרוע מ-~65מ'), **צינון שעה** לתא, **בדיקת-טלפורט** (מרחק/זמן מהכיבוש האחרון → מהירות בלתי-אפשרית → נדחה), הגבלת-קצב.
- **מפה:** Leaflet + אריחי OSM, הקסגונים מצוירים מ-`cellToBoundary` וצבועים לפי קבוצה, עדכון חי דרך Supabase Realtime. מיקום דרך `navigator.geolocation`.
- **מודל:** `territory` (h3 PK, team_id, user_id, nick, captured_at) = הבעלות הנוכחית; `territory_log` (append-only: user_id, h3, lat, lng, captured_at) לטלפורט ולמובילים בעתיד.

## היקף
- MVP: מפה חיה, כפתור "כבוש", צביעת ההקס, צינון, אנטי-רמאות צד-שרת, "כמה אזורים לכל קבוצה" (מונה חי).
- אחרי: טבלאות-מובילים מלאות (אוהדים/ערים), התראות, סטריקים, אפליקציה נייטיב להגנה חזקה.

## גלגול
מיגרציה + תלויות (h3-js, leaflet דרך web-deps) → staging → production (יאיר מריץ SQL) → מיזוג. בדיקת 375px.
